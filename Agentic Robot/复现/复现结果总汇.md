| 手工 split + Qwen verifier + OpenVLA | `libero_10` task 1 episode 0，object-level split `1/1`，但 verifier 未确认第一步完成，executor 在第一条子任务下完成整任务 |
| 手工 split + Qwen verifier + OpenVLA | `libero_10` task 2 episode 0，`turn on stove` 在 `t=120` 被 verifier 判定完成并切到 `put moka pot on stove`，最终 `0/1` timeout；同初始状态原始 baseline 成功 |
| `qwen-plus planner + Qwen verifier + OpenVLA` | `libero_10` task 2 episode 0，百炼 planner 生成同样 plan，verifier 在 `t=120` 切换，最终 `0/1` timeout |

结论：

1. 新版 `transformers` 的 VLM 环境没有破坏 OpenVLA executor 对原始任务指令的执行。
2. DashScope `qwen-plus` planner 路径已验证，之前的 LRM API key 阻塞解除。
3. 当前失败来自朴素手写 plan / object-level split / verifier 判断策略，而不是 OpenVLA executor 本身。
4. 当前 verifier 对状态类子任务可以触发切换，但切换后的 executor 子任务仍可能退化；当前结果不能代表论文完整 SAP 指标。

Goal2Skill / RMBench 的环境、assets、5-task demo 数据已恢复；DP/ACT/Pi0.5/X-VLA 的 5-task 50-demo 数据入口已打通；DP debug 训练 smoke、DP full-50 非 debug 2-epoch 短训、DP `observe_and_pickup` 单任务 600-epoch 训练、ACT 官方 1-epoch 训练 smoke、Pi0.5 1-step 训练 smoke 和 X-VLA 1-iter 训练 smoke 已通过；SAPIEN render 和真实 rollout 已通过；DP 300/600 checkpoint 的 5-episode sanity eval 均为 `0/5`；DP `observe_and_pickup` 600 checkpoint 的 100-episode 正式评估为 `1/100 = 1.0%`，与论文表中 DP 该任务 `1%` 对齐；但尚无完整 5-task、100-episode RMBench success rate。
