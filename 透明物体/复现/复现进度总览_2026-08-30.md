# 透明物体 baseline 复现总览（2026-08-30）

> **一句话结论：** P0 的单层/多层 gap 已经成立；TransCG 的 23,524 张完整测试已拿到，ReMake 复现了论文 Table I 的 Global Loss 行，DFNet 当前官方 release 已完成但不等同于论文原 checkpoint；T²SQNet 的 GT-mask、RGB/LangSAM、DFNet/ReMake 的同域外 ShellBench 读出和 fixed-planner 对比也已完成。即使可见 front depth 完美，interface F1 也只有 43.10%；完整 shell events 将固定候选的 collision-free selection 从 91.80% 提高到 100%，因此表示层 G0 gate 通过。

本文只记录本机真实跑过的结果。大模型权重、数据集和逐帧预测不入 Git；可执行代码、协议说明和汇总数字入库。

| 标签 | 它回答什么 | 本项目中的例子 |

## 3. P0：为什么单一 depth 不够

### 3.1 Booster：Depth4ToM Base 路径

| 方法 | All RMSE ↓ | ToM RMSE ↓ | ToM AbsRel ↓ | ToM δ1.05 ↑ | 论文 ToM RMSE |
| --- | ---: | ---: | ---: | ---: | ---: |
| MiDaS v2.1 Base | 120.53 mm | 140.40 mm | 0.12 | 36.30% | 140.31 mm |
| DPT-Large Base | 100.68 mm | 136.28 mm | 0.10 | 37.69% | 136.28 mm |

这两行复现了 Depth4ToM 官方 `run.py + evaluate_mono.py` 的 Base 路径。它们**不能改名为 Depth4ToM FT**。论文的 DPT FT Virtual Depth 为 ToM RMSE 83.06 mm，但对应 checkpoint 无法获得，只能保留为 paper-only reference。

### 3.2 LayeredDepth：单层与多层表示 gap

| 方法 | hypotheses | `layer_first` quad ↑ | `layer_all` quad ↑ |
| --- | ---: | ---: | ---: |
| DPT-Large Base | 1 | 56.198% | 29.954% |
| MiDaS v2.1 Base | 1 | 66.166% | 34.842% |
| SeeGroup release | up to 4 | 78.372% | 72.414% |

按较强的 MiDaS 行计算，`layer_all` gap 仍有 **37.572 个百分点**。mixed-layer quadruplet 上，MiDaS 与 DPT Base 都是 `0 / 195,800`，SeeGroup 为 `130,422 / 195,800 = 66.610%`。这说明单一 front depth 无法回答跨层 tuple；它是表示层面的证据，不是“Depth4ToM FT 必然同样失败”的证据。MiDaS/DPT 的 relative inverse depth 只做保序正比例归一化；不做这一步时，MiDaS 的任意输出单位会被官方 `0.02 m` 阈值错误地全部判 invalid。

### 3.3 SeeGroup 回到 Booster：还缺 metric bridge

| readout | ToM RMSE ↓ | ToM AbsRel ↓ | ToM δ1.05 ↑ |
| --- | ---: | ---: | ---: |
| closest layer，直接当米制 | 3372.31 mm | 3.7827 | 0.00018% |
| closest layer，Depth4ToM affine alignment | 65.54 mm | 0.0642 | 44.24% |

两者 RMSE 比值约 **51.46×**。结论不是 SeeGroup 本身失效，而是“多层相对结构”不能不经标定直接变成 Booster 的 metric single-depth。这正是我们需要 bridge/head 的原因。

详细分层计数见 [P0_gap_table.md](P0_gap_table.md)。

## 4. TransCG：真正可放进模型 baseline 表的完整测试

### 4.1 数据合同

- official test split：52 scene，23,524 sample；13 个数据分卷已全部下载、CRC/结构审计通过。
- DFNet 与 ReMake 都保存了 23,524 个 metric-depth prediction，并保留 source sample、相机、分辨率和缩放后内参。
- 分数同时报 `all` 与 `masked transparent region`；论文透明物体表主要看 masked 行。

### 4.2 DFNet：当前官方 release

同一 ReMake 640×480 官方预处理下，identity input depth 的 all/masked RMSE 为 **0.074009/0.167026 m**，masked REL 为 0.235197，masked δ1.05 为 43.82%。ReMake 将其 masked RMSE 降低 93.50%（约 15.39×）。这条 raw-input 对照不能与 DFNet 的 320×240、inpainting + per-image affine 预处理 raw 行合并；二者必须带各自 protocol 标签。

两条路径最大差异为 `0.00435` 个百分点（最严格的 masked δ1.01）；RMSE/MAE/REL 等差约 `1e-6` 或更小，交叉核验 PASS。

## 5. TablewareNet / T²SQNet：统一 shell benchmark

这部分不是 T²SQNet 论文原表复现，而是把 released model 接到我们定义的同一 multi-interface 表示与 evaluator。

### 5.1 一个已修正的重要协议错误

TablewareNet 的 `camera_image_size` 是 `[height, width] = [240, 320]`。旧 adapter 误按 `[width, height]` 读取，生成了 320×240 ray grid。当前已：

1. 修正相机射线；
2. 处理全部 100 scene；其中 98 个含 hollow GT 的 scene 重投影并进入 shell score；
3. 增加 shape regression test；
4. 作废旧 shell 指标，只使用路径名含 `hw_correct` 的新结果。

新 GT 覆盖 98/100 个含 hollow object 的 scene，共 259 个 hollow object、1,813 个 object-view event map，实际评分 139,238,400 rays。另 2 个 scene 没有 hollow GT，保留在 100-scene RGB/mask inference 分母中，但不伪造 shell events。

### 5.2 GT-mask oracle 与 RGB full baseline

| 项目 | GT mask oracle | RGB + official LangSAM |
| --- | ---: | ---: |
| inference scenes / shell-scored scenes / RGB views | 100 / 98 / 700 | 100 / 98 / 700 |
| predicted objects | 386 | 394 |
| matched hollow objects | 244 / 259 | 238 / 259 |
| object precision | 63.21% | 60.41% |
| object recall | 94.21% | 91.89% |
| interface precision | 81.54% | 78.96% |
| interface recall | 77.05% | 70.11% |
| **interface F1** | **79.23%** | **74.27%** |
| transition precision | 75.81% | 73.52% |

RGB 路径额外结果：700 view 的 LangSAM union-mask micro IoU 为 **95.27%**，F1 为 **97.58%**。尽管 segmentation 很强，最终 interface/transition F1 仍比 GT-mask oracle 低 4.96/4.46 个百分点，所以两条 baseline 必须分行报告。

RGB 路径保持了官方设置：prompt=`tableware`、5 次 hue augmentation、LangSAM ViT-H、released DETR3D/voxel heads 和 primitive reconstruction。GroundingDINO 只做了 PyTorch 2.8 所需的两处 `type() → scalar_type()` API 兼容补丁，不改模型语义。

### 5.3 DFNet / ReMake 接入同一 ShellBench

为避免把 TransCG RMSE 与 shell F1 跨协议硬比较，我们把同一批 TablewareNet
RGB、mask-zeroed depth 输入 released DFNet/ReMake，再用 GT object association
与 GT visible-front support 隔离 single-depth 表示本身。适配器不会补造后表面，
因此这是受控 unified-benchmark diagnostic，不是端到端模型成绩，也不是论文原生
分数。

| single-depth source | visible pixels 有有效 depth | interface P / R / F1 | matched MAE |
| --- | ---: | ---: | ---: |
| rendered front upper bound | 100% | 100% / 27.473% / **43.104%** | 0.545 mm |
| mask-zeroed raw control | 0.0102% | 100% / 0.0028% / 0.0056% | 2.021 mm |
| DFNet release（OOD） | 62.981% | 0% / 0% / **0%** | N/A |
| ReMake release（OOD） | 100% | 0.1377% / 0.0378% / **0.0594%** | 2.231 mm |

最关键的不是 OOD 模型接近零，而是 **完美可见 front depth 的 recall 也只有
27.47%**：缺失的是内壁与后侧界面，不能靠第一表面数值更准来补齐。DFNet/ReMake
的近零值还叠加了 TransCG→TablewareNet 的域移与 metric calibration 失败，不能
单独归因于表示。

同一 7,983 个 frozen candidates 上，actual model readout 的结果为：

| collision source | optimistic：safe / collision / reject | conservative：safe / collision / reject |
| --- | ---: | ---: |
| mask-zeroed raw | 223 / 21 / 0 | 223 / 21 / 0 |
| DFNet release（OOD） | 223 / 21 / 0 | 139 / 0 / 105 |
| ReMake release（OOD） | 223 / 21 / 0 | 104 / 0 / 140 |
| rendered front upper bound | 224 / 20 / 0 | 240 / 0 / 4 |
| GT full events | **244 / 0 / 0** | **244 / 0 / 0** |

因此 single-depth 的 unknown-space 策略形成明确两难：optimistic 会穿壁，
conservative 对 OOD completion 又会大量拒抓；完整 events 在同候选下同时消除
碰撞与拒抓。

## 6. 什么已经能放进论文，什么不能

### 可放进主 baseline 表

1. ReMake current release：TransCG 23,524，原生 masked metrics；与论文值并列。
2. DFNet current release：TransCG 23,524，明确标 current release；不要替换成 paper checkpoint 标签。
3. SeeGroup：LayeredDepth 300 张 official released checkpoint。
4. T²SQNet RGB full：只放在我们自己的 ShellBench 表，不放进 TransCG depth-completion 表。
5. DPT/MiDaS Base：可作为 single-depth / Depth4ToM-code-path 对照，名称必须保留 `Base`。

### 只能放 ablation / diagnostic

- T²SQNet GT-mask：oracle，不是端到端模型。
- GT first surface / GT events：表示上限，不是 learned baseline。
- SeeGroup raw-as-metric on Booster：cross-protocol stress test。
- TablewareNet shell GT：官方参数模型诱导出的 synthetic physical-shell oracle，不是真实玻璃内壁实测 GT。

### 仍不能声称

- “Depth4ToM FT 已复现”：权重不可得。
- “T²SQNet 的论文指标为 74.27%”：这是我们的 ShellBench interface F1。
- “已经得到机器人成功率”：当前只有 offline collision diagnostic。
- “已经训练 DepthHypothesisPack Head”：尚未开始，符合先验 gate。

## 7. 下一步实验顺序

1. 固定当前 train/val/test、event schema、candidate set、sampler guard 与 evaluator 版本；planner oracle 已通过表示 gate。
2. DFNet/ReMake 的同一 ShellBench event readout 与 actual-model planner 行已完成；冻结 per-scene/per-object failure slice 和 OOD 标签。
3. 训练最小 DepthHypothesisPack Head；先验证 interface/transition F1，再进入相同 fixed-planner collision gate。
4. 主表至少分成两张：`TransCG metric depth completion` 与 `ShellBench multi-interface / collision`，禁止跨协议直接排大小。
5. 最后再做真实透明物体与机器人 failure slice；offline oracle 不能替代执行实验。
