## 协议合同

### LayeredDepth

- 当前 README/SeeGroup 的输出命名使用 `i_1`, `i_3`, `i_5`, `i_7`。
- Depth4ToM 输出是 relative inverse depth；进入 LayeredDepth tuple evaluation 前只作每图正比例归一化（最大正 inverse depth 缩放到 1）再取倒数，不使用 GT，不改变远近排序。
- 单层方法只提供 layer 1。layer 3/5/7 是“缺失”，不能复制 layer 1，也不能把零值当作有效深度。
- `layer_first` 与 `layer_all` 分开报，且同时保存 numerator/denominator，避免只看比例。

### Booster / Depth4ToM

- Depth4ToM 官方 `evaluate_mono.py` 先把 prediction 归一化，再逐图对 GT disparity 做 least-squares scale-and-shift；它是 affine-aligned relative-depth protocol，不是 raw metric readout。
- SeeGroup first-layer 必须报两行：
  1. `raw-as-metric`：不做校准，直接把 closest valid layer 当米制 depth；
  2. `affine aligned`：先转 inverse depth，再走 Depth4ToM 官方 evaluator。
- 两行不能合并；否则无法判断缺的是层语义还是米制标定。
- SeeGroup 的官方训练 loss 使用 normalization alignment；因此第一行是刻意的 cross-protocol stress test，不是对其原生 LayeredDepth 任务的负面结论。

## 运行顺序

### 1. SeeGroup 逐级 validation

在 `透明物体/external/seegroup/official/` 下运行：

```bash
HF_HOME=../../../data/hf-cache \
CUDA_VISIBLE_DEVICES=0 \
conda run -n seegroup python val.py \
  --checkpoint-path ../../../weights/seegroup/seegroup.pth \
  --num-workers 0 \
  --max-samples 1
```

随后把 `--max-samples` 改为 `8`；两次通过后去掉该参数跑 300 张。

### 2. 缓存 validation teacher

从仓库根目录运行：

```bash
HF_HOME=透明物体/data/hf-cache \
CUDA_VISIBLE_DEVICES=0 \
conda run -n seegroup python \
  透明物体/复现/tools/seegroup/cache_validation.py \
  --official-root 透明物体/external/seegroup/official \
  --checkpoint-path 透明物体/weights/seegroup/seegroup.pth \
  --output-dir 透明物体/teacher/seegroup/layereddepth/validation \
  --cache-dir 透明物体/data/hf-cache \
  --local-validation-dir \
    透明物体/data/layereddepth/repo/data \
  --num-workers 0
```

### 3. 评测保存的 LayeredDepth predictions

```bash
HF_HOME=透明物体/data/hf-cache \
conda run -n layereddepth python \
  透明物体/复现/tools/layereddepth/evaluate_predictions.py \
  --prediction-dir <prediction_dir> \
  --subset layer_all \
  --npy-space depth \
  --layer-naming odd \
  --cache-dir 透明物体/data/hf-cache \
  --local-validation-dir \
    透明物体/data/layereddepth/repo/data \
  --output-json <metrics.json>
```

Depth4ToM 的 MiDaS/DPT Base 保存结果使用
`--npy-space relative_inverse_depth`。该模式只做保序正比例缩放，不能解释为
metric calibration。SeeGroup teacher cache 改用：

```bash
HF_HOME=透明物体/data/hf-cache \
conda run -n layereddepth python \
  透明物体/复现/tools/layereddepth/evaluate_predictions.py \
  --prediction-dir 透明物体/teacher/seegroup/layereddepth/validation \
  --prediction-format seegroup-npz \
  --subset both \
  --cache-dir 透明物体/data/hf-cache \
  --local-validation-dir \
    透明物体/data/layereddepth/repo/data \
  --output-json 透明物体/teacher/seegroup/layereddepth/validation/evaluation_both.json
```

## Gate

- `G0 / reproducibility`：LayeredDepth 与 SeeGroup 官方路径全量可跑；Depth4ToM 微调路径记录为 upstream artifact blocker，不伪造复现完成。Base fallback 单独验收。
- `G1 / gap`：以 MiDaS/DPT Base 中 `layer_all` 较强的 MiDaS 为 single-depth 主对照，再结合 SeeGroup-on-Booster 决定是否开始 Head。Base 结果只支持“单层表示局限”，不单独支持“Depth4ToM 微调模型也有同等 gap”。
- `G1 no-go`：现有方法在两个协议上都无明显错位，或所谓 gap 只来自错误的 depth/disparity 转换。

当前支撑感知线结论：`G0 PASS with FT artifact exception`，`G1 strong PASS`。但总项目当前主 gate 仍是 shell GT / grasp-failure G0；按总项目约束，不据此直接跳过主 gate 实现完整 shell head。Depth4ToM FT 的未跑数值继续保留 `TBD`，见 [`P0_gap_table.md`](P0_gap_table.md)。
