# G0：物理薄壳可行性与强基线总控

更新日期：2026-08-30

状态：**baseline reproduction 与 fixed-planner oracle 已完成；表示层 G0 gate PASS。** 最新精确数字见 [复现进度总览（2026-08-30）](复现进度总览_2026-08-30.md)。

## 1. G0 要回答什么

我们先不训练 DepthHypothesisPack Head，而是用现有强 baseline 回答两个问题：

1. 单张 front depth 是否会丢失透明容器的内壁、空腔和后表面？
2. 在**完全相同的候选 grasp 和 collision evaluator**下，完整 shell events 是否比 front-only 表示更安全？

只有第 2 个问题在固定 planner 下成立，训练新 head 才有清楚的因果理由。否则先修 benchmark / planner，而不是继续堆模型。

## 2. 冻结的比较边界

| 角色 | 方法 | 原生协议 | G0 中的身份 |
| --- | --- | --- | --- |
| RGB-D single-depth completion | DFNet | TransCG all / transparent-mask depth metrics | single-depth baseline |
| RGB-D + MDE + mask | ReMake | TransCG all / transparent-mask depth metrics | strong single-depth baseline |
| multi-view primitive model | T²SQNet | TablewareNet released model | RGB strong baseline；另报 GT-mask oracle |
| multi-layer teacher | SeeGroup | LayeredDepth validation | multi-layer structural teacher |
| support diagnostic | MiDaS/DPT Base | Booster / LayeredDepth | single-depth support line；不冒充 Depth4ToM FT |

以下指标必须分表：

- TransCG metric-depth RMSE/REL/δ；
- LayeredDepth quadruplet accuracy；
- ShellBench interface/transition F1；
- fixed-planner offline collision rate。

跨表数字不能直接排大小，也不能把 offline collision gate 写成机器人 task success。

## 3. 已冻结的数据与真值

### TransCG

- official test：52 scenes，23,524 samples，13 个数据分块齐全；
- 每个 metadata 项对应的 RGB、raw depth、refined GT depth 和 transparent mask 已审计；
- DFNet 与 ReMake 均已跑完 23,524 张原生入口并保存逐帧 prediction cache。

### TablewareNet physical-shell oracle

- test split：100 scenes、700 RGB views；其中 98 scenes 含 hollow GT 并进入 shell score；
- 259 个含 `superparaboloid` hollow component 的 GT objects；
- 1,813 个 object-view event maps，139,238,400 条 rays；
- `camera_image_size` 已按官方 `[height, width] = [240, 320]` 修正并做 shape regression test。

该真值是 **TablewareNet 参数模型诱导出的 synthetic physical-shell oracle**，足以做表示消融，但不是实测玻璃内壁真值。

## 5. 三个 planner oracle

候选一律来自 cached T²SQNet GT-mask predicted objects + released primitive grasp planner。GT 不参与候选生成，只进入离线 target-shell collision gate。

| policy | planner 看见什么 | 目的 |
| --- | --- | --- |
| GT-front conservative | first surface 后方全部视为 occupied | front-only 保守下界 |
| GT-front optimistic | 仅 first surface ±2 mm 视为 occupied | front-only 穿壁风险 |
| GT-events fixed parity | 所有 shell intersections 的奇偶占据 | 只替换表示，planner/候选不变 |
| GT-events shell-aware | 带 transition type 的完整 events，unknown fail-safe | 表示 + shell-aware 读出上界 |

## 7. Go / no-go 判据

1. 冻结候选集合、相机合同、shell event schema 和 collision 定义。
2. 对 front-only 与 full-events 的 collision-free selection rate 做 scene bootstrap 95% CI。
3. 当前 full events 相对 front-only 已有稳定、可解释的收益：表示 gate `PASS`。
4. 冻结本轮协议与审计结果后，进入最小 DepthHypothesisPack Head 训练。
5. Head 完成后，再接 DFNet/ReMake/T²SQNet/SeeGroup readout 做统一 failure slice；真实机器人实验放在最后。
