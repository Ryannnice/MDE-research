# G0：物理薄壳可行性与强基线复现总控

状态：进行中。TablewareNet / T²SQNet 的全量 `GT-mask` shell diagnostic 已完成；TransCG 的两条 native full-test 仍受官方 Google Drive 配额阻塞。G0 的目标不是训练新模型，而是完成可审计的现有 baseline，并验证“多界面/薄壳表示”是否能在**同一个固定 planner**下解释真实的几何失败。

## 冻结的比较边界

每个方法必须分开报告两类结果，绝不把跨协议读数混成论文复现值。

| 角色 | 方法 | 原生协议 | 进入 G0 的统一读出 |
| --- | --- | --- | --- |
| RGB-D single-depth completion | TransCG / DFNet | TransCG official test 的 all / transparent-mask depth metrics | `front` event（单一 metric depth） |
| RGB-D + MDE + mask | ReMake | 官方 `transcg_remake.yaml` test | `front` event（单一 metric depth） |
| multi-view object representation | T²SQNet | TablewareNet shape/recognition；需明确 RGB segmentation 或 GT-mask oracle | 预测 mesh 的 ray events；另报 mesh metric |
| multi-layer teacher | SeeGroup | LayeredDepth validation | 四层 ray events；只做 cross-dataset diagnostic，不伪称 TransCG metric baseline |
| support diagnostic | MiDaS/DPT Base、Depth4ToM code path | Booster / LayeredDepth | 单一 relative-depth event；不冒充不可得的 Depth4ToM FT |

`Trans2Occ` 目前没有可运行的官方代码/weight，不能列成 executable baseline；其位置保留为 related-work blocker，而不是用非官方重实现填表。

## G0 数据与几何真值

### TransCG：完整 native baseline

- 官方 test 分母固定为 **23,524**，横跨 52 个 scene、13 个下载分块。
- `tools/transcg/audit_transcg.py` 在评测前检查每个 metadata 指定的 RGB、raw depth、refined GT depth 和 transparent mask；不通过时全量运行器拒绝声明 `official_full_test`。
- TransCG mesh 可用于外表面/碰撞分析，但没有受控内壁厚度标注，因此**不**是 shell-topology GT 的主来源。

### TablewareNet：G0 主几何 oracle

T²SQNet 的官方 `mesh_superparaboloid` 直接构造 inner / outer pipe，并使用 `t=0.01`；这为 bowl、cup、dish 等 component 提供可重建的多界面几何。项目工具：

```text
tools/shellbench/tablewarenet_shell_gt.py
```

它将官方参数化 mesh 和相机位姿转成每像素有序 ray events。该真值的正确名称是 **TablewareNet model-induced physical-shell oracle**：它足以检验表示与固定 planner 的因果链，但不是实测玻璃壁厚数据。solid superellipsoid stem/bottom 以及多物体互相遮挡先不强行标为 cavity；主 G0 slice 只统计含 superparaboloid hollow component 的 object-centric view。

## 三个必要 oracle（不能省略）

1. `GT-front + fixed planner`：证明当 planner 只见 first interface 时，是否仍发生 cavity/through-wall collision。
2. `GT-events + fixed planner`：给 planner 完整的、无需学习的 physical-shell events；只有它改善才说明表示本身值得继续。
3. `GT-events + shell-aware planner`：表示与 planner 同时正确时的上界。

planner 选择、候选 grasp、碰撞阈值、对象/场景 split 在三个 oracle 中冻结不变。任一 planner 在生成候选时不得读取 GT；GT 只在离线碰撞/成功审计中使用。

## 指标卡

| 层级 | 必报量 |
| --- | --- |
| native reproduction | 原论文/官方定义的所有指标、checkpoint hash、commit、样本分母 |
| representation | interface P/R/F1、event-count accuracy、matched MAE/RMSE、transition/topology coverage；见 `tools/shellbench/` |
| geometry | shell wall-thickness error、cavity free-space false-positive、surface/mesh Chamfer（只在 mesh 方法可定义时） |
| planning | collision-free rate、through-wall/cavity collision rate、reachability、task success；95% bootstrap CI 按 scene 重采样 |

“raw metric” 与 “per-image affine aligned” 必须拆行；“GT mask” 与 “RGB predicted mask” 必须拆行；仅在表示与 planner 的输入完全一致时才可横向排名。

## 验收顺序

1. DFNet 和 ReMake 完成各自**官方全量 native test**，保存 per-sample prediction cache 与 manifest。
2. T²SQNet 先跑 TablewareNet `GT-mask` shape path，再跑 RGB segmentation path；两者分别报告。
3. 对 TablewareNet hollow-object slice 生成 shell events；检查至少一个 ray 同时出现 outer/inner event，且 topology-label coverage 足够高。
4. 跑三个 GT oracle。若 `GT-events + fixed planner` 不优于 `GT-front + fixed planner`，停止实现 DepthHypothesisPack Head。
5. 再将 DFNet/ReMake/T²SQNet/SeeGroup readout 接到同一 event + fixed-planner evaluator，做按 scene 的 bootstrap CI 和 failure slice。

通过第 4 步才开始训练新的 head。否则将结论收敛为“当前 planner/benchmark 未证明 shell representation 有效”，而不是继续堆模型。
