# 透明容器可见不可达取物任务：Idea 拷打与完整方案

日期: 2026-07-12

本文整理一个新的机器人透明物体场景任务：

> **Transparent Containment-Aware Object Retrieval**  
> 透明容器 / 透明屏障下的可见不可达目标取物任务。

核心设定：

```text
目标物在视觉上可见，但被透明盒、透明罩、玻璃杯、亚克力隔板、透明收纳箱或透明盖子物理阻挡。
机器人不能把“看得见”误判为“可直接抓”，而必须判断透明屏障、开口、盖子、容器边界和目标物之间的物理关系，再选择直接抓取、绕开开口、先移除盖子、先移动容器、主动观察，或拒绝动作。
```

本文目标不是宣称“绝对没人做过”，而是把这个 idea 拷打到一个更稳的科研问题：**透明材料造成的 visibility-reachability mismatch**。快速检索下，已有工作覆盖透明容器内重建、透明容器内容物理解、透明物体抓取、隐藏物体检索和透明物体长程操作，但我暂未看到一个直接以“目标可见但被透明 containment 阻挡，机器人必须做 reachability-aware retrieval”为中心任务的 benchmark / 方法。

Novelty status: quick-searched, not exhaustive。后续投稿前仍需做标准文献检索。

## 0. 一句话版本

透明材料让机器人出现一种普通遮挡没有的错误：目标物明明可见，却不一定可达。我们定义并研究 **transparent containment-aware retrieval**：机器人需要同时感知透明屏障的前表面、屏障后的目标物、容器开口 / 盖子 / 边界，并根据物理可达性选择动作，而不是把透射可见目标直接送给抓取器。

更短：

```text
Visual visibility is not physical reachability.
Transparent containment makes a target visible but not directly graspable.
```

## 1. 先拷打：这个 idea 最容易死在哪里

### 1.1 “没人做过”这个说法不能直接写

不能写：

```text
No one has studied transparent objects in robotics.
No one has used transparent containers in robot manipulation.
No one has studied objects inside transparent containers.
```

这些都不稳。已有近邻包括：

- 透明物体 depth completion / grasping：ClearGrasp、TransCG、ReMake、ASGrasp、ClearDepth。
- 透明容器内 3D 理解：ReNeuS / Seeing Through the Glass。
- 透明容器内容物 / 材料理解：TransProteus。
- 透明实验器皿操作：LucidGrasp。
- 透明物体长程语言操作：DeLTa。
- 遮挡 / 隐藏物体检索：RF-Grasp、UNOGrasp 类工作。

因此主张必须改成：

```text
快速检索未见一个直接面向 transparent containment-induced
visibility-reachability mismatch 的机器人取物任务和评测协议。
```

### 1.2 这个任务可能被质疑成“普通遮挡 / 清障抓取”

普通遮挡任务里，目标不可见或部分可见；这里的关键是：

```text
目标可见，但透明屏障是第一物理接触层。
```

如果论文只写“先移除障碍物再抓目标”，会被遮挡推理 / clutter removal / object retrieval 工作压住。

必须把透明材料的特有矛盾讲清楚：

| 普通遮挡 | 透明 containment |
|---|---|
| 目标不可见或少量可见 | 目标往往完整可见 |
| 视觉可见性通常暗示局部可达性 | 视觉可见性会误导抓取器 |
| 遮挡物边界通常清楚 | 透明壁 / 盖 / 开口边界常弱纹理、反光、深度失败 |
| 深度传感器多能看到遮挡物表面 | RGB-D 可能读到背景 / 目标物 / 空洞 |

### 1.3 这个任务可能被质疑成“透明容器内重建”

ReNeuS / Seeing Through the Glass 的任务是从多视图等观测恢复透明 enclosure 内部物体 3D geometry。它解决的是视觉重建，不是动作可达性。

我们的任务不能只是：

```text
reconstruct objects inside transparent box.
```

必须是：

```text
decide and execute a retrieval action under transparent containment.
```

也就是输出不是点云本身，而是：

```text
direct_grasp / grasp_through_opening / remove_cover / move_container /
active_view / reject
```

### 1.4 这个任务可能被质疑成“透明容器 / 液体操作”

LucidGrasp、TransProteus 等近邻会覆盖透明容器、液体、玻璃器皿。但它们重点不是“目标物被透明 containment 阻挡导致可见不可达”，而是容器 / 液体 / 材料 / 实验器皿本身的状态估计或操作。

因此第一版不要碰液体，不要写倒液体，不要写实验室自动化大系统。先做 rigid tabletop retrieval：

```text
透明盒 / 透明罩 / 透明隔板 / 透明杯中固体目标
```

### 1.5 这个任务可能太像 VLM 规划 demo

如果方法只是：

```text
把 RGB 图给 VLM，问能不能直接抓。
```

贡献会很弱。VLM 可以当 baseline，但主方法必须有机器人几何：

- transparent barrier layer。
- target layer。
- opening / rim / lid geometry。
- reachability graph。
- collision / path feasibility。
- action-conditioned readout。

### 1.6 数据采集可能成为最大瓶颈

要让任务成立，需要一套可复现场景：

- 透明盒、透明罩、亚克力隔板、透明杯 / jar。
- 目标物类别。
- open / closed / covered / side-opening / top-opening 变体。
- RGB-D failure。
- action labels 和成功 / 失败日志。

如果没有机器人实测，只能做 benchmark / simulator，机器人贡献会弱。最小策略是：

```text
先做物理 tabletop kit + 离线可达性标注 + 少量真实机器人闭环。
```

## 2. 快速近邻排雷

| 近邻 | 已覆盖 | 为什么不是直接覆盖 | 对我们的威胁 |
|---|---|---|---|
| ClearGrasp / TransCG / ReMake | 透明物体 depth completion / grasping | 主要抓透明物体本身，不处理“目标物在透明 containment 后可见但不可达”的 action selection | depth / RGB-D baseline |
| ASGrasp / ClearDepth | active stereo / stereo 透明物体重建与抓取 | 系统能力强，但重点是透明物体 reconstruction / grasp，不是 containment reachability | 系统上界 |
| ReNeuS / Seeing Through the Glass | 透明 enclosure 内部物体 3D 重建 | 无机器人 retrieval action 和 reachability decision | 视觉近邻，证明“容器内物体可重建”已有 |
| TransProteus | 透明容器中液体 / 固体 / 材料理解 | 偏实验材料和视觉理解，不是抓取取物 | 数据/视觉威胁 |
| LucidGrasp | 透明实验器皿、液面、瓶口和长程液体操作 | 操作对象主要是透明器皿 / 液体，不是取出被 containment 阻挡的目标物 | 场景相近，需明确非液体、非实验室器皿主线 |
| DeLTa | 透明物体长程 manipulation | 提供透明物体长程数据和策略，但未把 visibility-reachability mismatch 定义成核心 | long-horizon baseline / 数据威胁 |
| RF-Grasp | 借助 RF 找到并抓取被遮挡物体 | 目标通常不可见，且依赖 RF tag；不是透明材料下目标可见但不可直接抓 | hidden object retrieval 威胁 |
| UNOGrasp / occlusion reasoning | 普通遮挡下清障抓取 | 透明 containment 的深度失败和“看得见但不可达”不同 | 遮挡推理 baseline |
| TOPGN / transparent obstacle navigation | 透明障碍物检测与导航 | 移动机器人导航，不是机械臂取物 | 说明透明屏障可被定义为 physical obstacle |

## 3. 收紧后的正式问题定义

### 3.1 任务名称

推荐标题：

**Transparent Containment-Aware Object Retrieval**

中文：

**透明 containment 感知的可见不可达目标取物**

备选标题：

- **Visual Visibility Is Not Physical Reachability: Object Retrieval under Transparent Containment**
- **Seeing Is Not Reaching: Transparent Barrier-Aware Robotic Retrieval**
- **Containment-Aware Robot Manipulation through Transparent Surfaces**

### 3.2 一句话任务

给定一张或少量 RGB-D 观测，机器人需要识别目标物、透明 containment、开口 / 盖子 / 隔板，并判断目标是否可直接抓取；若不可直接抓，机器人需要选择正确的前置动作，例如移除盖子、从开口进入、移动容器、绕开隔板或主动换视角。

### 3.3 输入输出

输入：

```text
RGB image
raw depth
optional: multi-view / wrist camera view
optional: object goal phrase or target mask
optional: transparent material mask
robot gripper geometry and camera calibration
```

输出：

```text
TransparentContainmentGraph {
  target_object
  transparent_barrier_surfaces
  container_body
  lid_or_cover
  openings / rim / handle
  containment_relation
  visibility_relation
  reachability_relation
}

ActionPlan {
  direct_grasp
  grasp_through_opening
  remove_lid_or_cover
  move_container
  active_view_or_probe
  reject_as_unreachable
}
```

辅助几何输出：

```text
D_barrier: 透明屏障 / 容器前表面深度
D_target: 容器内 / 屏障后目标物深度
D_opening: 开口、边缘、可进入区域几何
D_lid: 盖子 / 罩子的可抓取几何
C_reach: 目标当前动作可达性的置信度
```

### 3.4 任务边界

第一版只做：

```text
刚性透明容器 / 透明屏障 + 固体目标物 + tabletop manipulator。
```

暂不做：

- 液体倒取。
- 软物体。
- 复杂抽屉 / 门把手机构。
- 完整家务长程规划。
- 大规模真实家庭场景。
- 完整透明光学重建。

## 4. 核心 insight

透明 containment 造成的是三层分离：

```text
视觉层：目标物可见。
几何层：透明壁 / 盖子 / 隔板是第一接触面。
动作层：目标物可能不可直接抓，需要前置操作。
```

传统 depth completion 或 grasping pipeline 往往默认：

```text
if target is visible and depth exists -> plan grasp
```

但在透明 containment 下应该改成：

```text
if target is visible:
    first estimate whether transparent containment blocks the path
    then decide action based on reachability, opening and removable parts
```

## 5. 方法蓝图

### 5.1 Representation: TransparentContainmentGraph

中心表示不是一张 depth，而是一个 action graph：

```text
Nodes:
  target
  transparent_wall
  transparent_lid
  container_rim
  opening
  support_surface
  gripper

Edges:
  visible_through(target, wall)
  inside(target, container)
  blocks(wall, direct_grasp_path)
  reachable_via(target, opening)
  removable(lid)
  graspable(container_or_lid)
  collision_risk(gripper, wall)
```

这个 graph 的作用是把视觉可见性转成物理可达性。

### 5.2 Perception: Layered Visibility-Reachability Pack

感知模块输出：

```text
LayeredReachabilityPack {
  D_barrier,
  D_target,
  D_opening,
  M_transparent_surface,
  M_target,
  M_opening,
  C_barrier,
  C_reachability
}
```

与 v4 `ContactDepthPack` 的关系：

```text
ContactDepthPack 关心抓透明物体本身。
LayeredReachabilityPack 关心透明 containment 后目标是否可达。
```

### 5.3 Action Reasoning: Reachability-Aware Skill Selector

动作选择器根据 graph 输出 skill：

```text
if target not blocked:
    direct_grasp(target)
elif opening exists and gripper fits:
    grasp_through_opening(target, opening)
elif lid_or_cover removable:
    remove_lid_or_cover()
    direct_grasp(target)
elif container movable and target can be accessed after moving:
    move_container()
else:
    active_view_or_reject()
```

### 5.4 Planning: Geometry Feasibility Check

不要只靠分类器。每个 skill 都要过几何可行性：

- gripper 是否穿过透明壁。
- 目标是否在容器内部。
- 开口宽度是否大于 gripper / target。
- 盖子是否可抓 / 可移除。
- 机器人路径是否碰撞透明 surface。

### 5.5 Learning Setup

可采用分阶段训练：

1. 透明材料 / 容器 / 目标 / 开口 segmentation。
2. `D_barrier / D_target / D_opening` layered depth / geometry prediction。
3. containment relation classification。
4. action skill label prediction。
5. policy fine-tuning 或真实机器人验证。

## 6. Benchmark 设计

### 6.1 场景族

| 场景 | 描述 | 关键失败 |
|---|---|---|
| Transparent Box Closed | 目标在透明盒中，盒子关闭 | 误判可直接抓 |
| Transparent Box Open | 目标在透明盒中，有侧开口或上开口 | 不会找到开口 |
| Transparent Cover / Dome | 目标被透明罩盖住 | 不会先移除罩 |
| Acrylic Divider | 目标在透明隔板后 | 直线抓取碰撞 |
| Transparent Cup / Jar | 小物体在透明杯 / jar 中 | 不知道从开口取、抓容器还是拒绝 |
| Mixed Clutter | 普通物体 + 透明 containment 混合 | 把普通遮挡和透明阻挡混淆 |

### 6.2 数据标注

每个样本至少标：

```text
RGB-D
target mask / class
transparent containment mask
barrier surface depth / proxy
opening / rim mask
containment relation
reachability label
required first skill
collision-free success / failure label
```

如果能做真实机器人：

```text
attempted skill
success / failure
failure type:
  hit transparent wall
  failed to remove cover
  grasped container instead of target
  missed opening
  target moved but not retrieved
  unsafe collision
```

### 6.3 指标

不要只报抓取成功率。建议指标：

| 指标 | 说明 |
|---|---|
| reachability accuracy | 目标是否可直接抓的判断 |
| first-skill accuracy | direct / remove / through-opening / move-container / reject |
| barrier collision rate | 规划或执行是否碰透明壁 / 盖 / 隔板 |
| opening localization error | 开口 / rim 几何是否准确 |
| target retrieval success | 最终是否取出目标 |
| unnecessary action rate | 明明可直接抓却先移除 / 移动 |
| unsafe direct-grasp rate | 明明被阻挡却直接抓 |
| layered depth error | `D_barrier` 和 `D_target` 是否分开 |
| active-view benefit | 额外视角是否降低不可达误判 |

## 7. Baseline 设计

### 7.1 Perception Baselines

- raw RGB-D + grasp planner。
- depth completion / transparent object depth: ClearGrasp、TransCG/DFNet、ReMake、ClearDepth if runnable。
- LayeredDepth / SeeGroup style multi-layer prediction as perception-only baseline。
- open-vocabulary segmentation + depth + rule planner。
- VLM-only action selection。
- VLM + depth / masks。

### 7.2 Manipulation Baselines

- direct grasp everything visible。
- ordinary occlusion-removal planner。
- containment-agnostic grasp planner。
- RF-Grasp style hidden-object retrieval only as non-comparable sensor-rich reference if tags are available。
- scripted oracle with GT containment graph as upper bound。

### 7.3 Ablations

| Variant | 去掉什么 | 看什么 |
|---|---|---|
| NoBarrierLayer | 不预测 `D_barrier` | 是否撞透明壁 |
| NoOpening | 不预测开口 / rim | 是否不会从开口取 |
| NoGraph | 无 containment graph，直接 action classifier | 是否泛化差 |
| NoDepth | 只用 RGB / VLM | 是否误判透明几何 |
| NoVLM | 只用几何，不用目标语义 | 是否目标选择差 |
| NoActiveView | 不允许主动换视角 | ambiguous case 是否失败 |
| GTMaskUpper | 使用 GT masks | 分离 perception 与 reasoning 上限 |

## 8. 论文贡献写法

推荐三项贡献：

1. **New task / benchmark**  
   定义 transparent containment-aware object retrieval，聚焦“目标可见但物理不可直接到达”的 visibility-reachability mismatch，并构建 tabletop benchmark / protocol。

2. **Representation / method**  
   提出 `TransparentContainmentGraph` 和 `LayeredReachabilityPack`，显式分离透明屏障、目标层、开口 / 盖子几何和动作可达性。

3. **Evaluation / findings**  
   证明普通 depth completion、transparent grasping、VLM-only planning 和普通遮挡推理在该任务上会出现系统性错误；action-conditioned reachability reasoning 能降低 unsafe direct grasp 和 barrier collision。

不要写：

- 我们首次研究透明物体机器人操作。
- 我们解决完整透明物体重建。
- 我们超越所有 transparent object grasping 方法。
- VLM 不能做这个任务。

可以写：

```text
Existing transparent-object manipulation work mainly focuses on reconstructing
or grasping transparent objects, while existing object retrieval work mainly
handles opaque occlusion or hidden targets. We study a complementary setting:
the target is visible through transparent containment but is not necessarily
physically reachable.
```

## 9. 实验最小闭环

### 9.1 MVP 数据

先做一个可控物理 kit：

```text
4 container types:
  closed clear box
  open clear box
  clear cover / dome
  acrylic divider

20 target objects
5 layouts per type
2 camera views per layout
```

第一版规模：

```text
约 400-800 RGB-D samples
约 100-200 robot attempts
```

如果机器人次数受限，先做：

```text
offline reachability labels + collision simulation + small real validation
```

### 9.2 MVP 方法

不从大模型开始。先做可解释 pipeline：

```text
RGB-D
  -> target / transparent surface / opening segmentation
  -> layered depth: barrier vs target
  -> containment graph construction
  -> geometry feasibility checker
  -> skill selector
```

这个 pipeline 容易做 ablation，也容易定位失败。

### 9.3 MVP 主表

| Table | 内容 |
|---|---|
| T1 | reachability / first-skill accuracy |
| T2 | target retrieval success / barrier collision rate |
| T3 | per-scene breakdown: box closed, box open, cover, divider, cup |
| T4 | baselines: direct grasp, VLM-only, depth+planner, transparent-depth+planner, ours |
| T5 | ablation: no barrier, no opening, no graph, no active view |

## 10. Reviewer 风险表

| 风险 | 类型 | 严重性 | 处理 |
|---|---|---|---|
| “这只是普通遮挡 / clutter removal” | writing/design-fixable | 高 | 强调目标完整可见但被透明物理层阻挡；加入普通 opaque occlusion 对照 |
| “这只是透明容器内重建” | writing-fixable | 高 | 主指标必须是 action selection / retrieval success，不是 3D reconstruction |
| “VLM 一句话就能判断” | evidence-fixable | 高 | 加 VLM-only / VLM+depth baseline，设计几何反例 |
| “数据太小 / 场景玩具化” | requires-new-result | 高 | 做多容器、多开口、多目标、多视角，公开 benchmark |
| “透明 segmentation 用 GT 不公平” | design-fixable | 中高 | GT / predicted / noisy mask 都报，GT 只作上界 |
| “没有真实机器人不算 manipulation” | evidence-fixable | 高 | 至少小规模真实 robot attempts；否则定位为 benchmark + protocol |
| “多层 depth 不是必须” | mechanism-fixable | 中 | 用 no-barrier-layer ablation 证明只看 target depth 会撞透明层 |
| “动作空间太复杂” | design-fixable | 中 | 第一版只做 5 个 skill，不做开放长程任务 |
| “透明容器材质变化泛化差” | requires-new-result | 中 | 多材质：玻璃、亚克力、半透明塑料；OOD split |

## 11. 关键实验反例

论文需要强 qualitative：

1. 目标完整可见，direct grasp baseline 直接撞透明壁。
2. depth completion 把目标物深度当成可抓深度，忽略前方透明盖。
3. VLM 识别出“盒子里有物体”，但没有精确判断开口 / 盖子几何。
4. 普通遮挡 planner 先抓错透明容器或把透明壁当空白。
5. 我们的 graph 判断 `inside(target, container)` 和 `blocks(wall, path)`，选择先移除盖子或从开口进入。

## 12. 最终收紧版本

成熟口号：

```text
Seeing through transparent containment is not the same as reaching through it.
```

成熟任务：

```text
Transparent containment-aware object retrieval:
given RGB-D observation and a target, infer whether the target is physically
reachable despite being visually visible, and choose the first manipulation
skill needed for safe retrieval.
```

成熟贡献：

```text
We introduce a new robotic retrieval setting where transparent containment
decouples visual visibility from physical reachability. We provide a benchmark,
a containment graph representation, and a reachability-aware manipulation
pipeline that avoids unsafe direct grasps through transparent barriers.
```

## 13. 下一步执行建议

最优先做的不是模型，而是验证这个任务是否有足够强的 baseline gap：

1. 搭 4 类物理场景：closed box、open box、transparent cover、acrylic divider。
2. 收 50-100 个 RGB-D 样本，手标 reachability 和 first-skill。
3. 跑三个低成本 baseline：direct grasp visible target、VLM-only action choice、depth+planner。
4. 看是否出现稳定错误：visible but unreachable、missed opening、barrier collision。
5. 如果 baseline gap 明显，再扩到 benchmark 和方法。

Go / no-go：

```text
Go:
  VLM-only 或 depth+planner 在透明 containment 场景稳定误判；
  barrier/opening graph 能显著降低 unsafe direct grasp；
  至少能做小规模真实 robot attempts。

No-go / pivot:
  若普通 VLM+depth 已能稳定判断全部场景，任务不够难；
  若数据采集无法超过玩具例子，改成 diagnostic benchmark；
  若真实机器人不可用，主张降级为 perception/action-selection protocol。
```
