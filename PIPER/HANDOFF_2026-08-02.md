## 踩过的坑与解决办法

### 坑 1：Windows 安装依赖时无法访问 GitHub

症状：

```text
Failed to connect to github.com port 443 via 127.0.0.1
ModuleNotFoundError: No module named 'can'
```

原因：Windows 的 Git/代理指向不可用的 `127.0.0.1` 代理。

解决：把官方依赖的固定提交打成离线 ZIP，放进 `remote_control/vendor/`，由 `setup_windows.ps1` 离线安装。不要重新执行依赖 GitHub 在线下载的旧版 `requirements-windows.txt` 流程。

### 坑 2：桥接端口出现 `WinError 10013`

症状：CAN 已连接且状态已打印，但 HTTP 服务绑定端口失败。

解决：早期桥改为 `--port 0`，让 Windows 自动选择可用端口；开机观察任务现在使用已验证可用的固定端口 `57845`。不要再强行使用当时失败的端口。

### 坑 3：浏览器访问桥显示 `401`

浏览器请求 `/` 或 `/favicon.ico` 得到 `401` 是正常的令牌保护，不代表 CAN 失败。`/v1/health` 可用于健康检查；完整 `/v1/state` 必须带令牌，推荐始终使用 `piper_client.py`。

### 坑 4：更新包路径错误或只解压了一部分

症状：

```text
Expand-Archive: piper_remote_control_update_v0.2.0.zip 不存在
start_control.ps1 不存在
```

原因：ZIP 实际位置与命令中的路径不同，或只复制了部分 v0.2.0 文件。

解决：最终完整目录已经部署到 `C:\Desktop\PIPER\remote_control`，版本为 v0.5.1。明天不要重新下载整个文件夹；先检查 `bridge_core.py` 中的版本和 health 输出。

### 坑 5：`agx_cando` 打开设备时一直卡住

症状：

```text
OPENING
... agx_cando\bus.py line 205 in _open_device
```

原因：CAN 适配器被旧的 `piper_bridge.py` 进程占用，或 Windows USB 驱动句柄没有释放。

解决顺序：

1. 确保只运行一个 PIPER 桥；
2. 停止旧桥，等待 CAN 关闭；
3. 必要时重新插拔 USB-CAN；
4. 先运行最小 `can.Bus(...)` 打开/关闭测试；
5. 再启动桥。

不要同时运行观察桥和控制桥，它们会争用同一个 CAN 设备。

### 坑 6：控制桥看似卡在 `Connecting ...`

这次并不是机械臂没有响应，而是 `agx_cando` 正被旧进程或 USB 句柄阻塞。通过进程检查和最小 CAN 测试定位后，重新插拔适配器恢复。

### 坑 7：OpenSSH Server 在线安装非常慢并失败

经历过的问题：

- Windows Optional Feature 安装长时间停滞；
- 首版脚本在用户尚未创建时调用 `sshd -T -C user=...`，出现 `_ga_init, unable to resolve user piper_remote`；
- 内置 `C:\Windows\System32\OpenSSH\sshd.exe` 服务曾以错误 1067 退出；
- 从服务器 `scp` 时密码输入失败；
- 临时手工补丁没有匹配到目标代码。

最终解决：打包 Microsoft Win32-OpenSSH 离线版本，校验 SHA-256 后安装到 `C:\Program Files\OpenSSH`，再用修订后的引导脚本配置账户、ACL、loopback 监听和计划任务。当前实际服务为 `OpenSSH_for_Windows_10.0p2`，运行正常。

`C:\ProgramData\PiperRemote\install-result.json` 中可能仍记录旧的 System32 OpenSSH 9.5 路径；这是安装阶段遗留信息。以 `Get-CimInstance Win32_Service -Filter "Name='sshd'"` 的实时结果为准。

### 坑 8：旧隧道需要手工保持窗口

早期使用过服务器端口 8765/8766，并且每次桥端口变化都要手工更新隧道。现在已经改成 Windows 开机自启的 SSH 反向入口 22022，服务器可以直接 `ssh piper-windows`。旧的 8766 窗口不是当前恢复链路的一部分。

### 坑 9：夹爪成功回零但 `homed` 仍为 false

这是当前 PIPER `S-V1.8-9` 的反馈特性。v0.5.1 已兼容，但会话级回零锁存不会跨桥重启保存。每个新控制会话需要重新确认闭合和回零，不能仅根据旧状态直接发宽度动作。

### 坑 10：把末端两针口误认为相机接口

PIPER/原厂夹爪使用 24 V 与 CAN；D455 需要 USB 3.x 的供电和高速数据。相机可以机械安装在末端，但不能电气连接到两个两针圆口。当前决定是先把 D455 作为固定场景相机，USB 直接接 Windows。
